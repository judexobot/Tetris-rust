# Firma de Android

Una actualización instalada requiere el mismo certificado que la versión instalada. Las versiones anteriores se construían con el certificado de depuración generado por cada runner cuando no había secretos: no hay garantía de que dos ejecuciones compartan firma y no se puede reconstruir la clave de un APK. Comprueba el certificado con `apksigner verify --print-certs archivo.apk`. Si difiere, exporta los datos antes de desinstalar la versión anterior; la desinstalación borra las preferencias de la aplicación.

Para una firma estable, configura los cuatro secretos del repositorio `ANDROID_KEYSTORE_B64` (contenido completo del keystore codificado en base64), `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS` y `ANDROID_KEY_PASSWORD`. El workflow falla si sólo hay una parte. La clave privada debe permanecer bajo control de su propietario; no se incluye en el repositorio, logs, artefactos ni Release. Guarda una copia segura del keystore y las contraseñas. Cuando los cuatro secretos estén ausentes se crea un APK de prueba con la clave de depuración del runner, que no garantiza actualizaciones entre builds. La firma del APK no cambia el `applicationId`.
